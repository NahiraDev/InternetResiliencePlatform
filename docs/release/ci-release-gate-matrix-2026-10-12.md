## Gate semantics checked

- `release-gate.yml` runs on `workflow_run` completion and fails closed: its verifier requires a successful `push` run of all 12 workflows on the same SHA. Today's `bf73303` Release Gate / Docker Publish runs show **SKIPPED** because they were triggered by `pull_request` workflow completions, which the gate intentionally ignores. They are not passes.
- `release.yml` refuses to publish unless a successful Release Gate run exists for the tagged commit, and always publishes with `--prerelease` until the production certification matrix passes.
- No `continue-on-error` or skip condition was added or changed by this work.
